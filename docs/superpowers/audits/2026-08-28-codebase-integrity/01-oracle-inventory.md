## Oracle independence decisions

- Real-Postgres tests independently exercise database mechanics, but their
  repository-authored expectations do not independently establish product
  meaning.
- The shared real/fake store contracts are a parity mechanism. They must never
  serve as two votes for the same claim.
- Raw PM5 bytes are independent input. A production decoder replaying them is
  still the subject under test; expected values need a hand decode, primary
  field definition, or independent PM5/logbook quantity.
- A fake-driven Playwright flow establishes browser integration and rendered
  consequences only. The fake is not a protocol, radio, firmware, or native
  lifecycle oracle.
- Coverage and mutation answer different questions: coverage proves entry;
  mutation proves an assertion bites; neither proves the expected value is
  externally correct.
- Production-build grep is artifact evidence only for its listed literals. A
  green grep becomes a trusted exclusion gate only after a known reachable
  listed literal makes it red.

## Highest-value discriminating probes

1. Hand-decode committed raw frames and compare work-only interval quantities
   with an independently identified PM5/logbook quantity; corrupt one decoder
   offset or reset boundary and require the comparison to fail (Tasks 5/8).
2. Exercise native background/foreground, Bluetooth-off, link loss, and
   recovery on a real device while correlating phone, recorder/ring, and PM5
   evidence; a web replay cannot substitute (Task 8; hardware only if Task 12
   says it can change ranking).
3. Temporarily make a listed dev-only monitor module statically reachable,
   rebuild, and require `dist-grep` to fail; reverse the mutation and prove a
   clean product diff (Task 9).
4. Corrupt one real/fake store behavior each around UUID validation,
   constraints, and transaction boundaries; require only the affected side of
   the shared contract to fail, then separately check the product invariant
   (Task 6/9).
5. Return successful malformed server payloads to installed-client readers;
   require a bounded error state rather than a ready state or render exception
   (Tasks 6/7).
6. Build a Playwright state/route/orientation matrix from actual test entry
   points, then enter every P0–P2 recovery arm with realistic stored data
   (Tasks 7/9).
7. Run an explicit import-graph cycle detector and inspect every reported
   strongly connected component before alleging circular architecture
   (Task 9).
