**Interfaces produced (Tasks 3-6 consume verbatim):**

```ts
export type CsafeFrameStatus = "ok" | "reject" | "bad" | "not-ready";
export type CsafeSlaveState =
  | "error" | "ready" | "idle" | "have-id" | "in-use"
  | "paused" | "finished" | "manual" | "offline" | "unknown";
export type CsafeResponse =
  | {
      kind: "parsed";
      frameStatus: CsafeFrameStatus;  // bits 4-5 (0x30)
      slaveState: CsafeSlaveState;    // bits 0-3 (0x0F)
      frameToggle: boolean;           // bit 7 (0x80) — NEVER tested for failure
      commandIds: number[];
    }
  | { kind: "unparseable" };
export function parseCsafeResponse(frame: Uint8Array): CsafeResponse;

export interface AckFrameOptions {
  frameStatus?: CsafeFrameStatus;  // default "ok"
  slaveState?: CsafeSlaveState;    // default "ready"
  frameToggle?: boolean;           // default false
  commandIds?: number[];           // default [] — the opcode echo
}
export function buildAckFrame(options?: AckFrameOptions): Uint8Array;
```

Bit values (cite csafe.h:747-766 via §19.1): frame status `ok 0x00`,
`reject 0x10`, `bad 0x20`, `not-ready 0x30`; slave state `error 0`,
`ready 1`, `idle 2`, `have-id 3`, `in-use 5`, `paused 6`, `finished 7`,
`manual 8`, `offline 9`, anything else (incl. `0x04`) → `unknown`;
building `unknown` emits `0x04`. Bit 6 (`0x40`) reserved: parse ignores
it, builder never sets it, one test pins that a set bit 6 still parses.
`REJECT_STATUS_BYTE` and the whole-byte compare die; the KNOWN-WRONG
banner comes off in this commit.

Tests that must fail against today's code (quote each failure):
- `0x81` → `frameStatus "ok"`, `frameToggle true` (today: "reject").
- `0x09` → `"ok"` + `slaveState "offline"` (today: "reject").
- `0x11` → `frameStatus "reject"` (today it happens to say "reject" for
  the wrong reason — assert the DISCRIMINATOR: `0x11` rejects while
  `0x81` accepts in the same test).
- A checksum-corrupted frame → `{kind: "unparseable"}`, and a test
  asserting it is NOT equal to any parsed reject.
- Vector matrix: 4 frame statuses × both toggles × (empty echo, 14-opcode
  echo — the real hardware shape from §19.1's captured ack
  `f1 01 76 08 18 01 17 03 04 06 14 13 77 f2` and its 0x81 twin).
