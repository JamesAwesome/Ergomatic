The erg drops the workout mid‑row

What a rower sees when the erg throws away the program while they are still rowing. Today the app notices this and does nothing: it keeps showing a live screen for a workout the erg no longer has, and the row is lost. This gate is the screen that replaces that.

Tokens are app/src/theme/tokens.css verbatim. Every ratio below is computed, not eyeballed. Frames are at real proportions: 372×640 portrait, 720×340 landscape.

The moment in between: the ended frame

Between the drop and the log screen, the existing SESSION ENDED surface renders for a moment (React paints it before the navigation effect runs). Today its machine-ended line would say "The monitor finished it. Your numbers are kept." — false here. These frames show what it says instead, in that surface's own voice: the mono status label, the 36px serif line, and the body line are the real elements at their real styles; only the body line's words change, branching on the new closeReason field.

The failed-write case is not new

If the record cannot be saved, the session does not hand off to the log — it holds in the state you already approved for PR #239, in the ended frame where that state actually lives, unchanged and shown here only so the whole path is visible in one place. Navigating away while the record never persisted is the exact harm §1 exists to stop.
