# Phase 5B — Builder, Bulk Import, Authoring Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a rower author their own workouts — a step-by-step builder with live-resolved splits, a bulk paste importer, and the edit/delete loop.

**Architecture:** No server changes: `POST /api/workouts`, `POST /api/workouts/bulk`, `PUT`/`DELETE /api/workouts/:id` and the `parseBulk`/`validateWorkoutInput` domain parsers all exist and are tested. Form state lives in a pure, separately unit-tested module (`builderState.ts`) so components stay thin; the builder screen serves both create (`/library/new`) and edit (`/library/:id/edit`) modes.

**Tech Stack:** React 19, react-router-dom 7.18.2, Vitest 4 + Testing Library, Playwright 1.62.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-29-phase-5b-builder-design.md`. `docs/design/` is the UI authority EXCEPT where `docs/design/DEVIATIONS.md` overrides. Builder layout: `docs/design/README.md` §Screens → "11. New workout (builder)".
- **Binding deviations:** pain is **1–5** (never 1–10); difficulty reads **EASY / MEDIUM / HARD**. "The Erg Book" must never appear in UI strings, code identifiers, or comments.
- **Hard requirements:** every tappable element ≥44×44px; all text WCAG AA (≥4.5:1); meaningful graphics ≥3:1 (WCAG 1.4.11); 2px radii; no shadows; no animation.
- **Colors come from tokens** (`var(--*)` in `app/src/theme/tokens.css`) — never raw hex in components.
- **The client mirrors the domain's bounds, never invents its own.** From `app/domain/validate.ts`: `num` 1..9999 · `title` 1..80 chars · `pain` 1..5 · steps a non-empty array, max 100 · `wu`/`r` minutes 0.5..180 in 0.5 steps · `w.spm` 10..60 · `w.restMinutes` 0.5..60 in 0.5 steps · `reps.count` 1..12 · at most ONE reps marker · a reps marker may not be last · at least one `w` or `test` step. The server remains the authority.
- **Duration grammar matches `app/domain/bulk.ts`'s `parseDuration` exactly**: `10'` → `{kind:"time", minutes:10}` (decimals allowed), `2500m` → `{kind:"distance", meters:2500}` (integer only). Typing and pasting must never disagree.
- Pace refs are parsed ONLY by `parsePaceRef` from `app/domain/pace.js` (regex `^(2k|6k)\s*([+-]\s*\d+(\.\d+)?)?$/i`) — never reimplemented.
- Domain imports use `.js` specifiers from client code (e.g. `../../domain/pace.js`); this works today — **do not add a Vite alias**.
- Screens must NOT import `@capacitor/*`, `./platform`, or `./native/*` (lint-enforced `no-restricted-imports`); platform behavior goes through `src/adapters/`.
- Tests assert real behavior, not mock behavior (docs/TESTING.md); no snapshots; no assertion-free tests. TDD: failing test first, RED evidence in the report.
- pnpm only, ESM only. Coverage gate 90×4; `domain/**` stays 100 (untouched this phase). Hooks must pass without `--no-verify`.

- [ ] **Step 3: Implement `builderState.ts`.** Notes that make the tests pass and keep the module honest:
  - Row ids: a module-local counter (`r1`, `r2`, …) — deterministic, no `Math.random`/`Date.now` (they break reproducibility and the domain forbids them by convention).
  - `toSteps` maps rows in order and emits `{k:"reps", count: f.reps}` immediately before the FIRST marked row. Emit it whenever at least one row is marked, including when `reps === 1` (the domain allows `count: 1`); emit nothing when no row is marked. The marker can never land last, because a marked row always follows it.
  - `ref` is parsed with `parsePaceRef`; a `w` row with an unparseable ref is an error keyed `row:<id>:ref`.
  - Empty `spm`/`rest` strings mean "omitted" — do not emit the field at all (matching `bulk.ts`).
  - After assembling, run the same bound checks the domain does and key each failure to its row/field so the UI can render inline. Do NOT call `validateSteps` and surface its index-based strings — those can't be mapped back to rows; mirror the rules with row-keyed messages instead, and keep the numbers identical to `app/domain/validate.ts`.
  - `totals`: sum unmarked row minutes into `loose`, marked into `perSet`, `total = loose + perSet * reps`. Distance rows convert via `resolveSplit(baselines, ref) * meters / 500 / 60`; return `null` if any distance row lacks baselines or a parseable ref.
  - `fromWorkout`: drop the `reps` marker from rows, set `f.reps` from its count, and mark every row at or after the marker's original position. Format durations back to `10'` / `2500m` and refs back to `6k-2` (no space, matching what the tests expect and what `parsePaceRef` accepts).
