# EST LEFT Implementation Plan (Phase LL)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The connected screen's remaining-time estimate keeps counting down through a rest instead of freezing when the rower stops moving, and can never jump backwards.

**Architecture:** Read the PM5's own Rest Time field (already parsed, consumed nowhere) for the live term inside a rest; keep programmed lengths for completed phases; clamp the running total monotonic. One task — it is a single coherent change and lands as one PR.

**Tech Stack:** Existing only.

- [ ] **Step 2: The monotonicity test, which is the one that matters.**

```ts
it("never lets the estimate jump backwards across a whole real capture", async () => {
  const frames = await loadCaptureFrames(SESSION_2);
  let prev = Infinity;
  for (const f of frames) {
    const m = buildSurfaceModel(/* ...the real inputs... */);
    const left = m.totalLeftSecondsRaw; // expose or derive; do not parse the display string
    expect(left).toBeLessThanOrEqual(prev + 1e-9);
    prev = left;
  }
});
```

This must include the capture's **`finished` frame** — that is where the old design dropped 428.5 s. Reasoning about monotonicity did not catch these; replaying did.

- [ ] **Step 3: Implement §1's rule.**

Completed phases contribute `phaseSeconds`; a rest in progress contributes `phaseSeconds(phase) − frame.restSeconds`; a work phase in progress contributes the interval clock. Then clamp `estElapsed` monotonic non-decreasing, and **keep the cap** so the bar's fill cannot exceed the session length (§2 — `min(x, T)` is load-bearing and the first draft of the spec would have removed it).

Guard the `null` `intervalIndex` the way `surfaceModel.ts:865-870` guards the AVG cell — against the RAW field, never the laundered local.

- [ ] **Step 4: Teach the fake to report Rest Time.**

`app/src/monitor/transports/fake.ts:746` hardcodes `restSeconds: 0`. Until it counts down honestly, **no e2e or screenshot fixture can exercise any of this**. Make it report the remaining rest the way the machine does, and check whether any existing fixture depends on the zero.

- [ ] **Step 5: The unpriced-phase guard.**

`phaseSeconds` returns `null` when a phase has neither seconds nor a meters+targetSplit pair — reachable on connected with null baselines (`engine.ts:88-94`, a distance warm-up). The phone timer hides the row via `hasRemainingEstimate`; `PaneLive.tsx` renders the cell unconditionally. Give it the same guard and test it with a null-baseline fixture.

- [ ] **Step 6: Read the two tests that pin today's behaviour BEFORE editing them.**

`surfaceModel.test.ts:1508` ("TOTAL LEFT subtracts the SESSION clock, never the interval's own resetting one") was added by an earlier antagonist pass as that suite's one discriminator. `e2e/connected.spec.ts:628` asserts the text changes across a 700 ms window. **If either needs changing, that is a finding for your report, not a quiet edit** — say what it protected and why the new behaviour still honours it, or does not.

- [ ] **Step 7: Self-mutation.** Remove the monotonic clamp (the Step 2 test reds); launder the null index back to `?? 0` (the finished-frame case reds); return the interval clock inside a rest instead of Rest Time (Step 1's test reds). Restore byte-identical, `git diff` clean.
