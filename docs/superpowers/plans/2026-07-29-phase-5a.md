# Phase 5A — Foundation, Library, Detail, Baselines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Ergomatic's first real screens — a design-token foundation, five-tab shell, filterable Library, Workout detail with live-resolved pace ranges and nudges, and a staged baseline editor — plus the app icon.

**Architecture:** `react-router-dom` provides real URLs (`/library`, `/library/:id`, `/you`) that the nginx SPA fallback already serves. The client imports `app/domain/` directly for all pace math (verified working with `.js` specifiers — no alias needed). Data comes from hand-rolled hooks over the existing `api()` adapter, following `src/useMe.ts`. Pure logic (chip filtering, baseline drafts) lives in separately unit-tested modules so components stay thin.

**Tech Stack:** React 19, react-router-dom 7.18.2, @fontsource 5.3.0 (newsreader/archivo/ibm-plex-mono), Vitest 4 + Testing Library, Playwright 1.62, Express 5.

router.get("/api/workouts", async (req, res) => {
  const userId = req.user!.id;
  // Two queries total, never per-row: lastDonePerWorkout is one grouped
  // query (see stores/logs.ts) — the library needs recency for every row.
  const [rows, lastDone] = await Promise.all([

    stores.logs.lastDonePerWorkout(userId),
  ]);
  res.json(rows.map((w) => ({ ...w, lastDoneDaysAgo: lastDone[w.id] ?? null })));
});
