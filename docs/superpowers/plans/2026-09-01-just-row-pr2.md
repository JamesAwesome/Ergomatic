## What rev 1 got wrong

Four findings, three of them structural. They are recorded here rather than
quietly fixed, because an implementer who reads only the tasks will
otherwise re-derive the same wrong model.

1. **"Everything downstream of `ready` is inherited unchanged" was false of
   the driver.** `phase: "ready"` and `activeRun` are opened by *different*
   things: rev 1's `beginFreeRow()` moved the hook, while `activeRun` is
   assigned in exactly one place — inside `program()`, `driver.ts:5992`.
   With it null, `runIsOpen()` is false and a free row loses three
   subsystems at once:
   - **No machine close.** `driver.ts:2579` returns before
     `emit({kind: "workoutComplete"})` and `emit({kind: "terminated"})`. The
     rower's Menu press — the walk's own observed ending — would reach the
     hook as nothing.
   - **No machine summary.** `driver.ts:2974` — *"out-of-window — 0x0039
     arrived before any `program()` ever opened a run … nothing filed"*. So
     `summaryTotals` and `verificationBytes` are unwritable: no MACHINE
     CONFIRMED and no verification code on any free row, while the walk
     decoded a perfectly good 0x0039.
   - **Auto-splits filed as phantom intervals.** `driver.ts:4438` sends the
     boundary down the out-of-run branch with `index: null`; harmless today
     because the hook drops it (`useMonitorSession.ts:2892`), but rev 1
     opens a record, and `recordActual` gates only on `wasClosed`, never on
     `index`. The walk fired two in 6.5 minutes.
2. **The two headline numbers had no persisted source.** `MonitorRun`'s
   field list (`monitorRun.ts:114-183`) carries no cumulative
   elapsed/distance pair. `series` is not a substitute: `Sample` carries
   `t`/`d` (`seriesRecorder.ts:219-224`) but the trace is whole-second
   bucketed, capped by `SERIES_SAMPLE_CAP` and self-declares
   `truncated?: true` (`:237-240`), so its tail is not the row's end on
   exactly the long rows this phase exists to support.
3. **The ended frame renders a false sentence, and no model change reaches
   it.** Covered by the Gate 0 amendment; see Task 5.
4. **Rev 1's divergence hazard did not exist.** `driver.ts:2548` is
   `if (p && intervalActive && intervalIndex === null)` — already gated on
   an armed program, with a comment saying exactly why. Rev 1 cited the
   callee's contract (`intervalIndex.ts:179`) and never read the caller's
   guard. **But see the ruling below: it comes back.**

## The ruling this rev is built on (James, 2026-09-01)

**Open `activeRun` for a free row.** That restores the machine close, the
0x0039 summary and correct boundary routing, and it makes the burst hold's
2-second *"Getting the monitor's own numbers."* an honest wait instead of a
promise the code could not keep.

**Its cost, which is the thing rev 2 must design around.** `armedProgram()`
returns `activeRun?.program ?? null` (`driver.ts:1774`), so opening a run
with a zero-interval program makes it **non-null** — and that re-arms both
things a free row must not have:

- the divergence escalation at `driver.ts:2548`, which would now fire on
  every frame of every free row (rev 1's hazard, false then, real now);
- the structure watchdog at `driver.ts:4948` (`if (armedWorkout !== null)`),
  which would compare the machine's readback against a zero-interval program
  and can emit `programDropped`.

**So `activeRun` gains a `freeRow: true` marker**, and each subsystem opts in
or out explicitly. The marker is on the driver's run, not inferred from
`program.intervals.length === 0`: `compileProgram` cannot produce a
zero-interval program (its own no-work guard), so a length test would be a
predicate with no second producer today and a silent trap the day one
appears.

| Subsystem | Free row | Why |
| --- | --- | --- |
| `runIsOpen()` — close, summary, boundaries | **in** | the whole point of the ruling |
| Divergence escalation (`:2548`) | **out** | no program to diverge from |
| Structure watchdog (`:4948`) | **out** | nothing was armed, so nothing can be dropped |
| Boundary `index` | **null, and refused by the hook** | Task 2 |
