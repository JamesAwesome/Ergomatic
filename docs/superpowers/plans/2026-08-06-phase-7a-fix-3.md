### Task 2: The settle — armed-plus-one, or say you gambled

**Files:**
- Modify: `app/src/monitor/driver.ts` (+`driver.test.ts`),
  `app/domain/monitor/types.ts` if `DriverOptions` lives there (it does
  not — it lives in driver.ts per the recorded deviation; extend it
  there)

**Interfaces produced:**
```ts
export interface DriverOptions {
  // ...existing...
  /** program()'s prepare-settle bound: after the prepare terminate
   *  closes a RUNNING piece, wait for state "armed" AND one further
   *  tick before sending frames, up to this many status ticks.
   *  Default 10 (observed dispatch→armed spans: 4 and 5 ticks — §18
   *  session 3; the 3-tick settleTicks default is provably too small
   *  and that option is a DIFFERENT, state-blind mechanism).
   *  0 disables (session 4b's detection row uses this). */
  prepareSettleTicks?: number;
}
```
New log kinds: `prepare-settle` (the wait began: prior state named),
`prepare-settle-expired` (bound hit without armed; proceeding — Stage
2's readback is the net; log says so).

Behaviour (spec §1b, all binding): the wait arms ONLY when the state at
prepare-send was `rowing`/`resting`; end condition is an `armed` tick
FOLLOWED BY one more tick (any state); `terminated` and `idle` are NOT
settled (the traces show the cycle passing through both — cite §18
session 3's two sequences verbatim in the comment); expiry proceeds
(never rejects) with `prepare-settle-expired`; a NEW pendingPrepareSettle
slot, not `pendingSettle` (that slot's disconnect-resolves comment is
only true for terminate()'s use — a disconnect during THIS wait must
fall through to sendSequence's own `"disconnected"` failure, test it);
settled-state programs add ZERO ticks (latency pin: count status ticks
consumed by a main-menu-state program() against today's — equal).

Tests that must fail today: a program over a rowing-state stub waits
through terminated/idle and sends only after armed+1 (today: frames go
out immediately after the prepare ack); expiry proceeds with the log
entry; `prepareSettleTicks: 0` disables; the latency pin; disconnect
mid-wait → `"disconnected"`. Mutations: release on `terminated` → the
wait test dies; drop the +1 tick → its pin dies; bound 3 → the
4-and-5-tick trace replays die. Full gates; 100% driver.ts.
Commit: `feat: program() waits for the machine to finish changing its mind`.
