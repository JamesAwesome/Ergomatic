# Just Row PR 2 — surface, session and log door

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** a rower taps JUST ROW on Today, connects, pulls, and the machine's
own free row lands in the log as a `session_logs` row with no workout, no
targets and no plan advance.

**Architecture:** one session engine, two surfaces. `useMonitorSession`
gains a **free-row arm** that reaches `phase: "ready"` without sending a
byte to the erg; everything downstream of `ready` — the motion-triggered
record open, the series recorder, close reasons, the hand-off store, the
lifecycle and silence machinery — is inherited unchanged. The live screen is
`ConnectedSurface`, given a free-row `SurfaceModel`. Only the entry door and
the log door are new components.

**Tech stack:** React 19 + Vite client, Express 5 API, Drizzle/Postgres,
Vitest (unit/client/integration), Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-08-24-just-row-design.md` (rev 4).

`docs/design/handoffs/2026-09-01-just-row/README.md` — copy-final.

### Task 2: the interval key for an empty program

**Files:**
- Modify: `app/domain/monitor/pm5/intervalIndex.ts` or `app/src/monitor/driver.ts:2159-2163`
- Test: `app/domain/monitor/pm5/intervalIndex.test.ts`, `app/src/monitor/driver.test.ts`

**Interfaces:**
- Consumes: Task 1's free-row record (`program.intervals.length === 0`).
- Produces: no signature change if the fix lands at the driver's call site.

**The problem, stated exactly:** `toProgramIndex` returns `null` for
`programLength <= 0`, and the driver escalates a `null` to a
**`"divergence"` log entry** whenever `machineState` was `rowing`/`resting`.
A free row is `rowing` with a zero-length program for its whole duration, so
today every frame of every free row writes a divergence entry. The series
recorder's interval key pins at 0 either way.

**Decide and record which layer takes the fix.** `intervalIndex.ts`'s own
doc comment calls `programLength <= 0` "no program armed yet", which is an
assumption a free row falsifies — so the honest fix is at the driver's call
site, where the caller knows it has a free row and can skip the escalation.
Changing `toProgramIndex`'s contract instead would make it claim an interval
0 that does not exist.

- [ ] **Step 1: Write the failing test.** Drive the driver over a
      zero-interval program with rowing frames and assert **zero**
      `"divergence"` entries in the event log, and that the frame's
      `intervalIndex` is `null`.
- [ ] **Step 2: Run it and watch it fail** with the divergence count.
      `pnpm test --project unit -- driver`
- [ ] **Step 3: Implement** the free-row branch at the escalation site.
- [ ] **Step 4: Re-run**, plus the replay suites, which drive real walk
      bytes through this exact path: `pnpm test --project unit`
- [ ] **Step 5: Commit, then probe** by restoring the escalation and
      confirming the new test goes red.
