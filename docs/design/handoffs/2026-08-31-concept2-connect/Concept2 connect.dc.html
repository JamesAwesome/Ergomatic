NOTES FOR THE GATE
COPY UNDER APPROVAL
FLAG · weight class ask is conditional. James (this review): do not ask H/L if Concept2 already has a weight class on the account. Check after the OAuth exchange (or via the API if it exposes it); ask only when blank on Concept2. The rendered ask (1a) stays in the design for that case. Open question for PR0: whether the API exposes the account's stored class — GET /api/users/me as documented returns no weight field, which may force the ask anyway; if so this flag needs a ruling.
The H/L ask (1a, conditional per the flag above): "Concept2 requires a weight class. Asked once, at connect." Options "H · HEAVYWEIGHT" / "L · LIGHTWEIGHT", helper: "Lightweight: 61.5 kg or under (women) · 75 kg or under (men). Otherwise heavyweight."
Duplicate (2d): "Concept2 already has this row: same date, time and distance. Nothing changed."
Unlink confirm (1d): "Unlink removes this app's access. Rows already sent stay on Concept2." Armed label "Tap again to unlink", 4 s auto-disarm.
DECISIONS THE SPEC LEFT TO DESIGN
Non-qualifying rows: absent. Manual and terminated rows never qualify, so a disabled control would sit on them forever explaining itself. The block simply does not render; the You card is the teaching surface.
Not linked: nothing on the row. The Concept2 block renders only when an account is linked. The You card is the sole discovery surface.
Sent is past tense (2c): "Concept2 accepted this row · date." The logbook is the rower's; if they delete the row there, our record stands and the link-out 404s honestly. Sent renders only when the row's Concept2 account matches the live link.
Pre-pick Connect: until a class is picked the Connect block is dimmed (border #c9c3b2, label #57544c) and inert; disabled state, AA-exempt but still 7.4:1.
